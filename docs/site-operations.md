# LandReady 적용·운영 기준

확인일: 2026-10-10. 사용자 후보 C1–C63, H1–H32의 전체 대조 원장은 `standards-95.json`이다. 총 95개 중 쿠폰·건강 전용 구성 2개를 제외한 93개는 적용 후보이며, 중복을 포함한다. STANDARD_DEFINED는 문서 기준만 정했다는 뜻이며 구현·발행·검증 완료가 아니다.

## 콘텐츠와 근거

여행 경로·입국 신고서 작성 의도를 우선하고 같은 의도는 기존 URL을 수정한다. 현재 디자인, 번호, 다국어 항목명, 입력·변환·복사를 유지한다. 미지원 목적지에 확인하지 않은 규정을 채우지 않는다. 관련 공식 안내를 연결하며 별도 허브나 페이지 수 목표를 완료 조건으로 추가하지 않는다.

공식 기관, 제3자 데이터, 사용자 보고를 구분한다. 각 수치·조건에는 출처, 적용 경로·대상, 원문 게시일(확인 가능한 경우), 조회일, 검토일, 실제 검증일, 효력일을 따로 기록한다. 조회 실패는 정보 변경·만료로 처리하지 않는다. 출처 해시 변경은 검토 후보이며 자동 승인하지 않는다. 출처 충돌은 대상·조건·시점을 비교하고 미해결 차이를 남긴다. 안전 정보 변경, 수치 오류, 출처 충돌 순으로 검토한다.

## 검색·공유·품질

Blogger 홈과 Worker 작성 도구의 역할을 구분한다. 작성 도구의 의도적인 noindex를 유지한다. canonical에는 검증된 경로 코드만 넣으며 사용자 입력·알 수 없는 쿼리를 넣지 않는다. 화면 내용에 맞는 제목·설명·WebPage 구조화 데이터·OG를 제공하며 없는 작성자·발행일·평가를 생성하지 않는다. 브랜드·파비콘·이미지 설명·사용 권리 기록을 유지한다.

Search Console·Search Advisor·Bing은 등록, 제출, 수집, 색인, 노출, 유입 상태를 따로 기록한다. 과거 확인 증거는 보존하되 다른 도메인의 현재 상태로 일반화하지 않는다. IndexNow는 지원·소유권·키·예산을 확인한 뒤 별도 적용한다. 사이트맵은 실제 공개 글 원장과 대조하기 전 전체 검산 완료로 보고하지 않는다. lastmod는 실제 내용 변경 시에만 갱신한다. URL 변경 시 기존 주소 연결을 보존한다.

정적 검사와 공개 점검은 `npm run check`, `npm test`, `npm run build`, `npm run audit:public`로 분리한다. 공개 점검은 지정한 5개 대상만 순차 조회하고 각각 20초 제한, 자동 재시도 없음으로 실행한다. HTTP 성공은 색인·규정 정확성·입력 성공의 증거가 아니다. 변경 해시를 검토하고 깨진 링크·이미지·리디렉션을 수정한다. 전체 링크 도달성은 공개 URL 원장이 확보된 뒤 검사한다.

UI 변경 시 PC 및 360/390px 실제 렌더링, 넘침, 키보드·터치·포커스·확대·대비를 확인한다. 이미지 크기·반응형 표시·필수 로딩을 유지한다. 광고·팝업·공유 버튼이 입력을 방해하지 않게 한다. 실험실 성능과 실제 사용자 성능은 별도 결과로 기록한다.

## 측정·홍보

현재 분석 서비스 연결과 실제 검색 데이터는 미검증이다. 향후 이벤트는 copy_success(클립보드 쓰기 성공), official_link_click, share_success(실제 공유 완료), revisit를 따로 정의한다. 복사 성공·공식 링크 이동을 입국 신고 제출 성공으로 표시하지 않는다. 이름·생년월일·전화·주소·서명·입력 원문·개인 쿼리 URL을 분석 데이터에 보내지 않는다. 운영자 방문·중복·결측·지연을 구분한다.

검색 개선은 실제 검색어·노출·클릭률 및 비교 기간·표본·변경일에 근거한다. 유입이 낮다는 이유만으로 글을 삭제하지 않는다. 유지·보강·통합은 유효성·중복·독자 효용으로 판단한다. 홍보는 요약과 원문 링크를 사용하며 `utm_source` 채널, `utm_medium` 방식, `utm_campaign` 캠페인 이름을 일관되게 기록한다. 외부 게시·계정 연결·유료 실행은 별도 승인 범위 확인 후 실행하며 게시 URL·날짜·실제 결과를 남긴다.

## 실행·복구

조사 담당은 원천·검토 후보, 작성 담당은 내용·변경 이유, 실행 담당은 지원 도구·권한·비용, 검증 담당은 실제 테스트·공개 증거를 기록한다. 원고, 구현, 테스트, commit, push, 배포, 공개 검증, 검색 성과는 서로 다른 단계다. 색인·노출은 발행 완료 조건이 아니다.

재시도 전에 실제 반영 상태와 checkpoint를 확인하며 실패 지점부터 재개한다. 최소 변경과 Git 복구 경로를 확보하고 무관한 변경을 보존한다. 오류 신고는 접수→검토→수정→검증 상태, URL·재현·담당·근거를 기록한다. 공개 연락처가 정해지기 전 신고 UI를 가짜로 제공하지 않는다.

현재 유료 기능 허용 예산은 0이다. 구독 요구·권한 부족·반복 실패 시 해당 도구를 중단하고 AUTOMATION_BLOCKED로 기록한다. 2026-10-10 GSC Wizard의 Google/Bing 목록 조회가 구독 제한으로 차단됨. 서비스 자체 장애로 판정하지 않는다.

정기 검토 제안은 안전·출처 변경 수시, 기술 오류 발행 시, 검색 성과 월별이다. 일정 자동화는 아직 생성하지 않았다. 증거 없는 점검 완료 보고를 하지 않는다.
