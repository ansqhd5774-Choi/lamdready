# LandReady 수동 점검

사용자 선택: 정기 실행 없이 수동 점검. 예약 작업을 만들지 않는다.

## 1. 공개 상태

현재 작업 폴더에서 `npm run audit:travel`을 1회 실행한다. 요청 한도35, 동시3, 타임아웃20초, 자동 재시도0. 중단/관찰 timeout 시 checkpoint와 최종 결과에 사용하는 `artifacts/travel-current-audit.json`의 실제 상태를 확인하고 무조건 재실행하지 않는다. 외부 서비스 인증 정보나 입력 원문을 로그에 추가하지 않는다.

정상 기준은 공개 홈/현재 작성폼/정적 자산 응답, 기존 글 삭제 유지, 의도한 noindex, 링크·이미지 속성 점검이다. 공개 글0은 결측이 아닌 현재 콘텐츠 상태다. 외부 공식 링크는 원문 검수가 필요한 경우에만 확인한다. HTTP 성공을 입력 동작·색인·규정 정확성 완료로 바꾸지 않는다.

## 2. 검색 상태

`data/search-status.json`의 현재 LandReady 주소만 사용한다. 등록·소유권·제출·수집·색인·노출·유입을 각각 기록한다. 이미 제출된 사이트맵을 반복 제출하지 않는다. Processing/처리중/데이터 없음은 실패나 성과0으로 바꾸지 않는다. 오류 상태가 바뀌거나 새로운 오류 근거가 있을 때만 해당 지점에서 진행한다.

## 3. 분석

LandReady 전용 속성/스트림을 사용한다. 운영 점검 브라우저는 홈의 `#lr-operator` 링크로 제외하고, 일반 방문 시험이 필요할 때만 `#lr-visitor`로 복구한다. 시험 후 운영자 모드로 되돌린다. 브라우저 저장소 초기화/다른 프로필에서 제외 설정은 자동 유지되지 않는다.

실제 요청과 제공자 실시간 수신을 별도로 확인한다. 표본의 관찰 시간·시험 횟수·운영자 시험 여부를 기록한다. page_view 요청1건과 실제 이용자1명을 동일 개념으로 보지 않는다. 당일 또는 처리중 보고서를 장기 결측/지연 결과로 판단하지 않는다. 작성폼에 GA 태그를 추가하거나 입력값을 전송하지 않는다.

## 4. 판정과 재개

변경·실패가 확인된 범위만 수정하고 영향을 받은 검사만 실행한다. 접속 불가/도구 제약과 실제 서비스 실패를 구분한다. 소유권 토큰·원시 분석 식별정보·개인정보는 저장하지 않는다. 점검 결과는 `docs/travel-final-execution-20261010.md`와 해당 상태 원장에 연결한다. 외부 홍보 채널, 공개 연락처 및 새 콘텐츠는 임의 생성하지 않는다.

수동 운영의 첫 실행 근거: `artifacts/travel-current-audit.json`(20요청 PASS), `artifacts/operator-exclusion-runtime-20261010.json`(0/0/1건 및204), `artifacts/landready-ga-received-20261010.png`, `artifacts/bing-landready-submitted-20261010.png`. 이는 기존 실제 검증 증거를 재사용한 것이며 새 검사를 실행했다는 뜻이 아니다. 정기 운영의 영구 성공을 보장하지 않는다.
